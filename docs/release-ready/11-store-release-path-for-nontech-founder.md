# DuongDuong 学中文 — Store Release Path for a Non-Tech Founder

## Mục tiêu
Nếu sau này bạn muốn đưa app lên mobile store, đây là con đường khả thi nhất.

---

# Phase 0 — Chưa lên store ngay
## Mục tiêu
Chứng minh app dùng được và có người thích.

### Việc nên làm trước
- web public trước
- beta 5–15 người
- sửa bug lớn
- polish content HSK1
- chốt positioning

---

# Phase 1 — Chuẩn bị store assets
## Bạn cần chuẩn bị
### Product basics
- app name
- subtitle / short description
- full description
- app icon
- splash screen
- screenshots
- privacy policy
- terms of use
- support contact

### Technical basics
- app slug
- app version
- Android package name
- iOS bundle identifier
- build config

---

# Phase 2 — Build mobile packages
## Với Expo, hướng dễ nhất là
- dùng **EAS Build**

### Bạn sẽ cần
- Expo account
- EAS CLI
- Android/iOS config cơ bản
- app identifiers

### Build outputs
- Android: `.aab` hoặc `.apk`
- iOS: `.ipa`

---

# Phase 3 — Store accounts
## Google Play
### Cần
- Google Play Developer account
- phí một lần

## Apple App Store
### Cần
- Apple Developer account
- phí hàng năm

---

# Phase 4 — Store listing
## Bạn cần điền
- app title
- description
- screenshots
- icon
- category
- privacy info
- contact info
- support URL nếu có

---

# Phase 5 — Review & publish
## Google Play
- thường dễ hơn Apple
- hợp để lên trước

## Apple App Store
- review chặt hơn
- cần polish hơn
- dễ bị hỏi thêm về purpose / privacy / app completeness

---

# Vesper khuyên thứ tự
## Nếu sau này muốn lên store
1. lên web trước
2. lên Play Store trước
3. lên App Store sau

---

# Cái gì có thể gây kẹt với founder non-tech
- chưa có app identifiers
- chưa có store metadata
- chưa có legal pages
- screenshots chưa chuẩn
- build signing chưa rõ
- app chưa đủ polished nên bị reject hoặc feedback xấu

---

# Cách khả thi nhất
## Giai đoạn đầu
Tự làm:
- content
- landing
- demo
- legal basic
- screenshots
- metadata

## Giai đoạn store build
Nếu thấy khó, có thể:
- thuê dev/freelancer hỗ trợ 1 lần
- nhờ họ xử lý build + store submission

Đây thường là cách tiết kiệm hơn cho founder non-tech.

---

# Kết luận thực dụng
### Bạn nên tự làm trước
- web-first release
- beta validation
- store assets

### Bạn có thể cần hỗ trợ sau
- EAS build
- Play/App Store submission
- final mobile polish
